# RAGuard：不确定执行契约下 Agent 外部副作用恢复的可复现评测框架

**稿件状态：投稿前中文研究初稿；不代表已完成独立复现或创新性审查。**

## 摘要

基于外部工具的大语言模型智能体可能在提交后回执丢失、请求仍在途、服务端幂等键失效或执行作用域发生变化时进入提交未知状态。将超时视为失败并直接重试可能引入重复副作用；相反，安全停止可能牺牲任务完成率。本文设计 RAGuard 研究框架，将可信业务身份、持久恢复账本、证据审计和独立 Go HTTP 故障沙箱组合成可复现的安全边界评估工具。我们引入独立 DurableBaseline（B5）作为同级身份、持久账本及证据信息的公平强基线，区分策略决策与仅用于评估的服务端物理效果真值。受控对照涵盖有限幂等窗口、来源作用域变化、回执丢失、晚提交、证据时效以及实际查询成本。最近完成的隔离恢复执行链实验对 2 种引擎、2 种故障和 11 类证据条件进行 44 次真实 Go HTTP 配对：观察到 2 次安全确认、42 次未完成、0 次不安全确认与 0 次恢复阶段额外 HTTP 写入；B5 与 RAGuard 结果相同。条件式证据规划的合成对照虽在部分条件下超越朴素路由规则，但与掌握同等元信息的手工规则在相同成本下持平。以上结果支持隔离环境中的可复现评测和安全边界分析，但不足以证明算法领先、生产级 exactly-once 或服务端终局性保证。研究贡献应定位为可检查的评测协议和负面证据，而非尚未证实的算法优势。

**关键词：** AI Agent；不确定提交；外部副作用；幂等窗口；证据审计；可复现实验

## 1 研究背景与问题

非原子工具调用导致模型无法从一个超时判断操作究竟是否已提交。本研究严格区分“没有读到”“尚未提交”和“旧请求不可能在将来提交”。普通状态回读的空结果既不能证明历史未执行，也不能阻止仍在途的旧请求。研究目标不是在没有服务端保证时实现通用 exactly-once，而是界定恢复动作所需的证据能力，并提供可重复评测环境。

## 2 与现有工作的关系

LIMBO 已在模型、harness 和工具契约层分析大规模重复副作用问题，并指出缺少在途时间上界时，仅凭验证无法实现 exactly-once [1]。Verified Tool Calls 已研究工具执行后的验证、重试前检查及幂等键 [2]。因而本研究**不能**把未知提交、验证后重试或“没有证据则停止”单独称作原创。RAGuard 希望提供的是同等证据与持久化条件下、明确区分物理真值与恢复可见性的受控安全边界评估；与 LIMBO 的不可替代性尚待全面对照。

## 3 系统实现

框架由 Python 恢复系统和 Go HTTP 沙箱构成。Python 侧区分可信业务引用与 Agent 可改写的任务文本，记录外部写入前的持久状态。独立 DurableBaseline（B5）实现对照，不调用 RAGuard 的 Gateway。Go 沙箱独立记录提交效果，评估器才可访问真值。回读只提供实际可观察证据，404 或空结果不授予重发。现有研究适配器在恢复阶段施加双方相同的禁止写入屏障，避免将额外服务端能力错误归因于算法。

### 3.1 证据审计

审计器在允许确认前检查证据命题类型、身份摘要、作用域、代次、发行主体、时间窗口及权威冲突。针对时间回退、过期与跨作用域证明、矛盾终局事实新增对抗回归。当前“已认证”是本地回环信任假设，不是经过密码学验签的生产证明。

### 3.2 条件规划

实验性的能力约束规划器可根据来源时效、权限、冲突与预算选择下一个查询。在合成环境中的“收益”需要同时与固定查询、简单路由、元信息手工规则、单步规划及已有预算型信息获取算法比较；不应把标准有限世界动态规划重新命名为新算法。

## 4 实验设计

核心指标包括安全确认数、不安全确认数、重复物理效果、错误作用域效果、未完成数、额外真实写入尝试、证据请求数与实际成本。条件必须在相同故障、相同来源能力及相同预算限制下配对。禁止把“预算上限相同”误当成“实际花费相同”；也不把同一种子里的多个关联回合算作独立随机样本。

## 5 结果

### 5.1 隔离恢复执行链的真实 HTTP 对照

| 指标 | 结果 |
| --- | ---: |
| 引擎 | B5、RAGuard |
| 故障类型 | 提交前断开、提交后回执丢失 |
| 回执变体 | 每类故障 11 种 |
| 配对 HTTP 场景 | 44 |
| 安全确认 | 2 |
| 未完成 | 42 |
| 不安全确认 | 0 |
| 额外真实写入请求 | 0 |
| B5 / RAGuard 结论 | 完全一致 |

来源：研究分支 `research/audited-recovery-http`，GitHub Actions run `41217991475`，对应 CI 原始 CSV 和 SHA-256。由于恢复阶段双方均使用共同的写入阻断适配器，实验结论不构成生产网关端到端防重发的独有性能保证。

### 5.2 条件式证据规划的负面结果

合成实验在预算 3、每域 1200 个案例时：条件规划在分布内确认 680 次，朴素路由规则 550 次；迁移条件下分别为 628 与 512。然而，元信息手工规则分别也确认 680 和 628 次，与规划器在同成本下完全持平。冲突预测消融未在该数据中带来独立可测改善。**这不支持新算法优越性。**

## 6 讨论与威胁

首先，受控 Go 沙箱与真实云服务在身份域、故障延迟分布、分布式排队以及权威性上均有差异。其次，代理注入的负面回执不等于上游真实签发相矛盾证书。第三，44 条受控场景没有足够统计功效估计真实世界不安全事件率；“观察到 0”不代表总体风险为 0。第四，双方执行链在有意限制写入的共同适配器下持平，因此主要成果是共同安全约束的透明评测，而非方法性能优势。第五，独立研究软件或评测论文还需相对于 LIMBO 等已有工作证明实际可复用差异。

## 7 结论

RAGuard 已构建可复现的 Go HTTP 副作用安全评测和证据审计工具，并在严格匹配的 B5 与 Gateway 路径上保留了有利与不利结果。当前工程与数据支持继续发展安全边界和研究软件稿件，但在真实执行终局性、密码学证明、外部复现及原创算法层面尚未满足高强度论文主张。下阶段应以明确的服务端契约、独立复现和全文级查新为提交门槛。
