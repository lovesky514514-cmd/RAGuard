## 3. 文件边界与研发接口

| 层 | 当前文件 | 下一阶段职责 |
|---|---|---|
| 入口 | `raguard/http.py` | 默认关闭匿名写；明确身份、权限，不作为生产认证 |
| 业务身份 | `raguard/model.py` | 新建 `raguard/identity.py`，同一业务实体和幂等键绑定；不能由 Agent 伪造 |
| 工具契约 | `raguard/policy.py` | 增加稳定键是否真受服务端保证、回读一致性、可补偿限制 |
| 持久事实 | `raguard/ledger.py` | 保留原子 CAS；明确可证明状态迁移和事件实体关联 |
| 安全判定 | `raguard/gateway.py` | 拆成证据检索、可行动作集、动作选择，避免多职责 if/else |
| 外部服务 | `raguard/transport.py` | 严格区分服务端肯定拒绝与提交结果不确定 |
| 假服务 | `mock/main.go` | 支持随机强度、late commit、响应篡改、回读滞后 |
| 数据判定 | `bench/oracle.py` | **本次新增的纯数据判定器雏形**，不基于 HTTP 200 判断正确性 |
| 实验 | `bench/` | B0–B5、注入矩阵、统一种子、统计分析；除 oracle 外尚未实现 |
| 漏洞复现 | `audit/reproduce_known_gaps.py` | 当前两项 OPEN，后续修复时必须能关闭 |

## 4. 首批风险 / 不变量

- INV-01：同一受控业务键不得被可变 step/intent 绕过去重。
- INV-02：幂等资格必须由真实服务契约证据支持，不能凭模型声明。
- INV-03：HTTP 超时或 `readback=None` 不推导服务端未提交。
- INV-04：代次落后的执行者不得覆盖更新的执行结果。
- INV-05：仍存在已提交/不确定下游时，不允许孤立补偿上游。
- INV-06：不可逆、无服务端幂等保证的重复执行默认拒绝。
- INV-07：回放缓存结果须与权限/有效期/真实状态契约相容，不等于重新执行。
- INV-08：评测以真实状态与历史副作用为准，而非 HTTP 成功或 Agent 的自述。

INV-01/07 当前有明确复现；INV-04/05/06 当前基础测试通过。其他尚需扩展测试。
