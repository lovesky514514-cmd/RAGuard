# 投稿前的双路线决策与可复现验收

## 当前结论（2026-11-01）

**开发验证：** 最新隔离持久恢复链 GitHub Actions 运行 41217991475 和 41218064316 成功。44 组 Go HTTP 配对包括两种引擎、两种故障和 11 类回读变体；2 次安全确认、42 次未完成、0 次不安全确认、0 次新增 HTTP 写请求。原始 ZIP、协议及 SHA-256 已核查。

**算法路线：** ECF/CCEP 没有在同成本同信息的强规则下形成稳定优势。CCEP 在合成预算 3 中与元信息手写规则持平。禁止宣称“首次提出验证后重试”“首次发现晚提交风险”“首创预算条件动态规划”。

**科研软件/评测路线：** 已有可运行 Python+Go 框架、独立 B5、回环 HTTP 注入、来源和时间约束、结果和哈希归档，但与既有 LIMBO 的独立贡献尚未全文核实；可以准备投稿材料，暂不可宣称已满足期刊审稿标准。

## 可复现入口

- 审计恢复执行链：`python -m bench.audited_recovery_http --output results/audited_recovery_http`
- 完整回归：以仓库 `.github/workflows/ci.yml` 为准；执行需 Python 3.11+、Go 1.21+。
- 数据：GitHub CI 的 `audited-recovery-http-ci` 工件，含 `episodes.csv`、`protocol.json`、`REPORT.md`、`SHA256SUMS.json`。
- 特别限制：研究适配器禁止再次写入，未调用真实厂商服务，回执不含有效数字签名，没有服务端不可绕过的 fencing。

## 下一次投稿前必须真正完成的三项验收

1. **外部契约：** 由第二套独立 Go 服务或实验室系统提供可验证签名结果、请求覆盖范围、旧请求失效/不可再提交的服务端保证；对轮换密钥、撤销、旧 worker 延后、跨作用域等场景测试。不能在缺少不可绕过的 fence 时重发危险写入。
2. **贡献对照：** 全文对照 LIMBO、Verified Tool Calls、既有幂等契约、序贯信息获取和 POMDP，逐项标示 RAGuard 已覆盖/未覆盖。若贡献只在相同现有安全机制下取得与 B5 同等表现，则稿件按可复现评测工具定位。
3. **投稿文件：** 独立机器或实验室 CI 复现、稳定归档标识（发行提交和 DOI）、完整正文图表与统计、版权/作者贡献/基金/数据许可、目标期刊收录与费用核查。导师确认后才能提交。

## 两条路线如何决策

- **A 算法稿：** 只有在相同可见证据、相同实际成本且与强规则/标准规划同条件对照时，出现独立可复现的新增安全能力或效率优势，且可证理论贡献，才升级为新算法稿。
- **B 工具稿：** 优先完善面向可复现安全边界的工具接口、软件质量、用户文档、独立环境复现与和现有基准的差异。该定位同样需要文献审查与期刊验证，不是“软件能运行就能录用”。

## 作者需要提供的最少信息

真正到投稿前才需要：导师是否认可“软件/基准”为论文主要贡献、作者与单位的准确英文写法、共同作者和贡献、拟用期刊或学校认定标准，以及独立复现实验的机器或服务端契约。API Key、真实支付凭证或私人数据均不需要。

## 风险与停机线

如果服务端无法提供旧请求不可再提交的保证，则只能保持未知而不能授权重发；如果同级 B5 完全追平，不能宣称恢复算法优势。当前不做无限制扩大合成实验，不合并研究适配器到正式 Gateway。
