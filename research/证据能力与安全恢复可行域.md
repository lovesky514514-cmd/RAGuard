# RAGuard：可验证证据能力与恢复可行域研究

## 研究判断

已验证的 HTTP 配对实验展示了有限去重窗口、跨作用域与晚到提交的安全/完成率取舍，但 B5 与 RAGuard 在等信息条件下持平。该结果**不是新算法超过强基线的证据**。研究问题保持不变，新的独立候选方法只在这里验证，不修改正式 Gateway。

现有相似工作：
- [LIMBO / Where Does Exactly-Once Live?](https://arxiv.org/abs/2609.29095)：在途时间无上界时，仅依靠验证不能保证 exactly-once，且已覆盖延迟提交、幂等键、Agent 框架对照。该机制不能再作为首创。
- [Verified Tool Calls Improve LLM Agent Reliability Under Non-Atomic Failures](https://arxiv.org/abs/2608.02645)：已研究验证后重试、后置条件及幂等键。
- [IETF Idempotency-Key draft-08](https://datatracker.ietf.org/doc/html/draft-ietf-httpapi-idempotency-key-header-08)：明确键生命周期和资源方契约；是草案而非最终 RFC。
- [Execution Finality Foundations draft](https://datatracker.ietf.org/doc/html/draft-das-execution-finality-foundations-00)：已提出签名结果、非执行证据和权限终局性的概念；尚非正式标准。
- [The Scheduler Is a Hidden Retriever](https://www.paperpeel.com/paper/2610.26310)：调度影响证据获取，不能把动态采样本身称为首创。

**定位**：候选创新不是“加证书”“安全停止”“优先查证”“按 TTL 拦截”，而是对**有限证据预算、时效窗口与权威信息不一致**建立可复核的安全恢复可行域，明确哪些证据组合支持哪些执行权限，并对安全且可确认的任务比例/查询成本给出可证伪比较。是否具有独立新颖性仍需全文级文献对照与实证。

## 核心研究问题

**RQ1：安全可行域**。在请求可能晚提交、幂等键可能过期、执行作用域发生改变的条件下，不同来源/时间/业务身份/完成状态的证据何时足以授权确认或重新派发？是否能构造互相不可比较的证据能力组合，使“更多证据条数”并不总带来更多安全行动？

**RQ2：有限预算**。给定同样的查询次数、最大等待、费用和来源权限预算，候选策略能否通过选择值得查询的权威来源，得到更多**经过真实物理账本验证**的安全确认，而不增加任何不安全写入？如果只是调用更多 API 才有收益，不算方法有效。

**RQ3：不完全契约**。缺少服务端终局性、在途上界或清理时间保证时，能否区分“可确认成功”“已证明未执行且可安全重发”“必须保持未知”？不得把一次查询返回空结果解释成从未提交。

## 受信任证据语义

证据必须绑定：tenant、principal、tool、稳定业务引用、参数摘要、作用域、服务端代次或可验证序列，以及发行主体。判定依据包括：
- `POSITIVE_COMMIT`：由对该效果具有确认权的来源证明发生过指定提交；只允许确认，不自动授权重新执行。
- `FINAL_NON_EXECUTION`：有对应作用域及请求覆盖保证的终局性证明，表明旧请求不会再产生副作用；若没有消除旧在途执行的可能性，不授权重新执行。
- `PENDING`：该业务可能仍在途；不得重发危险写入。
- `ABSENT_READ`：状态回读未找到；不是不执行证明。
- `CONFLICT` / `EXPIRED` / `UNTRUSTED`：强制停止并升级。

只有持久可信身份、服务端权威范围、正确时效及独立签名/认证检查同时满足，证据才可以用于决策。即使非执行证明有效，在目标服务端没有排他写入、持久 fencing 或不可被旧请求绕过的执行屏障时，**不得据此自动重发**。

## 方法候选：Evidence Capability Frontier（暂定）

用受信任来源所具有的**可证明能力**而非简单置信度评分构建决策可行域。每个动作输出三类之一：

1. `CONFIRM`：权威、绑定且未失效的正向提交证据，且没有冲突；对真实效果进行后验评估。
2. `REISSUE`：须同时存在终局未执行证明、旧请求不可在未来提交的排他机制、相同业务身份与有效目标作用域/重试契约；安全性要求由服务端保证。
3. `STOP`：以上任一证据缺失、冲突或超预算；显示理由并保留未解决状态。

策略可以在预算内选择下一个证据查询，但是**不能根据失败或超时对未知提交状态猜测重发**。增加证据源后的安全性不应下降是一个有条件命题：新增的伪造或互相矛盾证据必须触发停止，不能被多数票覆盖。

## 最小反例和行为测试

| 条件 | 预期动作 | 依据 |
| --- | --- | --- |
| 原请求未确认、回读空白 | STOP | 没有排除晚提交 |
| 原请求可能在途，客户端时间尚在 TTL 内 | STOP | 客户端计时不是服务端执行屏障 |
| 正向提交证明身份、作用域、版本相符 | CONFIRM | 只确认、不重发 |
| 正向证明来自其他租户或旧代次 | STOP | 不能跨身份归因 |
| 已证明未执行，但旧工作者仍可能提交 | STOP | 非执行证明不具备未来约束 |
| 已证明未执行且获得不可绕过的服务端 fence | REISSUE 或等待，取决于重试契约 | 需要服务端执行许可 |
| 两个有效权威来源互相矛盾 | STOP | 不可按数量投票 |
| 超出查询预算 | STOP | 预算不放宽安全前提 |

**强基线**：无重试 B0、已实现独立 DurableBaseline B5、B5+同级证据、RAGuard+同级证据、相同预算固定证据查询、同预算随机/轮询、理想 oracle 仅作上界。证据服务能力必须公平分配，不能只给候选方案更高级的证书或 fence。服务器物理效果仅评估器可见。

**控制因素**：有效签名、过期与吊销、作用域迁移、回读一致性、并发 worker、请求排队延迟、实际 TTL、证据成本、来源真实性、时钟漂移。按业务域和故障分层，保存独立随机种子、逐案例 HTTP 记录、结果摘要、SHA-256、双平台 CI。对配对安全性报告不安全物理效果/错误确认，对效率报告安全确认率、未完成率、证据查询次数、等待时间和置信区间（仅对真正独立随机样本适用）。

## 可证伪标准和停止条件

- 在相同证据能力、时间与调用预算下，若所有强基线可实现同等安全完成率和费用，承认方法没有实证优势。
- 若收益完全来自增加新的服务端契约而非策略设计，将其归因为**契约能力提升**，而非 RAGuard 算法创新。
- 若跨故障分布反转时成本/完成优势消失，报告排名反转，不做筛选式汇报。
- 若与 LIMBO、现有序贯信息价值/分布式事务及近期 Finality 草案在定义和实验上实质重合，暂停算法独创性主张，转为边界基准或更换问题。
- 没有可信旧请求终局证据时，不声称实现 exactly-once，不为提高指标重试危险写入。

## 研发约束

只在 `research/contract-evidence` 分支进行研究；`2.0` 是经双平台 CI 验证的研究基线，`main` 保持不变。正式 Gateway 不允许因研究方便而改变默认执行授权。新增 Python / Go 注释与维护文档使用中文、UTF-8 无 BOM，文件开头不写冗长解释，禁止长分隔线；错误只追加仓库唯一的 `docs/问题记录.md`。

## 已完成研究的判定（2026-10）

- 有限窗口、跨作用域、在途晚提交：真实 Go HTTP 对照已保存，B5 与 RAGuard 同级信息下结果持平。
- 正向回读、证据能力判定：隔离的 ECF 判定原型已实现负面测试；没有实现生产可用的签名终局证明，也没有通用安全重发机制。
- 静态校准选择：等实际成本的固定 quick 能完全解释观察到的收益，不能称为算法超越。
- 在线滑动窗口 UCB：已有方法作为强基线，在环境切换后能调整来源，但不保证优于固定来源。
- 真实 HTTP 多回合：无预算、精确累计花费和累计上限三种协议均有独立实验数据；精确花费会引入强制改选，上限模式则会跳过查询，不能混合比较结论。
- 已保存的两种子八案例四组烟雾基准：预算 8、12；两引擎全部对应结果持平；两个种子不足以报告可信统计优势。原始数据和摘要哈希已逐项校验。
- 后续的研究工作不应继续把相同查询策略换名做更多确定性回合。当前证据支持**实验边界与评测贡献**，暂不支持独立算法优越性。

## 科研定位与对外承诺

**目前可交付**：可复现的真实 HTTP 故障环境、独立 B5/Gateway 配对机制、证据查询预算/迁移强基线、消融和数据完整性检查。可以撰写边界/评测型研究稿，但需要核对同类文献并获得独立复现，录用没有保证。

**目前不能声称**：ECF 新颖性已证实、显著优于 B5、生产级 exactly-once、具备签名执行终局性、验证过独立真实厂商、零不安全风险。

**剩余必须由外部验证的条件**：独立环境重复、权威签名证据和服务端 fence 的真实安全语义、全文相关工作差异、投稿目标与合作者作者贡献。没有这些时，不应继续以增加模拟案例数替代贡献论证。

**当前状态：算法创新假说仍开放；本阶段的可复现评测组件与已核实的正反结果已收敛，尚不能直接承诺 SCI 可录用。**
