# Window Live 第一轮完整配对实验记录（冻结样本）

- **实验层级**：Go 独立 HTTP 子进程 + 真正的 B5 SQLite DurableBaseline 和 RAGuard Gateway 调用入口；无生产服务。
- **样本总量**：26 个预设条件，每条件 B5 / RAGuard 各一条，共 **52 条真实 HTTP 轨迹**。
- **初始不确定性**：原始请求的两次网络响应丢失（提交前或提交后），两种方法都用持久状态恢复。
- **服务器时间**：固定 tick=0 首次请求，之后恢复时刻 tick=2、4、6；去重期限 4 tick（精确实验实现，非厂商 TTL）。
- **作用域**：保持原地域或切换地域；恢复时刻由监督器推进，并且上一请求已退出。
- **契约准入**：两种方法都可以获得同等可信最小保留期、最早可能接收时刻和原作用域；未知期限一律不授权再次写入。
- **证据**：该 Go 服务没有独立最终提交回读，故恢复只见响应或回读缺失；回读函数调用次数 != HTTP 回读请求数。
- **安全评分**：效果日志由实验监督器在恢复结束后独立取得；状态码不等于物理完成。

## 数字的解释

相同实验条件下 B5 与 RAGuard 的各类案例结果持平。这说明两者共享契约准入后，能避免本矩阵中已模拟的重复与错域写入，代价是更多未决案例；不意味着两者的真实分布式性能等价，也不代表独立创新。

**特别保留的局限**：契约信息中的最早可能接收 tick 是实验已知事实；真实客户端可能面对未知时钟偏差、在途原始请求、未知清理时间，此时不能依据此实验规则安全地继续写入。这里的零错误不是对真实 API 的安全认证。两组均共用相同契约门禁，该门禁并不属于 RAGuard 的独特算法。

## 数据文件

- `episodes.csv`：按条件逐条记录网络尝试、重复物理效果、错域效果、确认及墙钟恢复时间。
- `summary.csv`：固定矩阵描述性统计。
- `fault_contracts.json`：冻结服务端模型、故障点和基本安全假设。
- `REPORT.md`：自动生成的原始人类可读汇总。
