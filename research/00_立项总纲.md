# RAGuard · 研究总纲

日期：2026-10-23 ｜状态：**立项审查 / 尚无论文实验证据**

## 研究范围

针对工具 Agent 的外部 API，研究**提交结果不确定（ambiguous commit）**时：
1. 哪些业务副作用已经发生，哪些仍在执行，哪些根本无法判定？
2. 哪些自动恢复动作不会增加不可接受的副作用风险？
3. 当 API 的幂等、回读、一致性、补偿能力各不相同时，能否在安全与完成率之间获得强基线以外的可测收益？

最终论文**不应**写成「第一次把幂等键、回读、账本、重试放进 Agent 网关」。这些机制均有重要先行研究。

## 不允许越过的条件

- HTTP 超时不是「未提交」的证据；回读不存在也不是「未提交」的证据。
- 没有服务端幂等保证、可靠协调或有界处理时间时，不承诺通用 exactly-once。
- 在代理无权判断两个订单是否相同时，不能靠自然语言相似度构造唯一业务键。
- 保持真实任务成功率与不安全副作用分开统计；保守拒绝不能自动当成获胜。
- 不使用真实支付、邮件投递、生产系统作混沌实验。

## 候选贡献（待证伪）

C1. **可信业务意图绑定**：受控的 business key / 参数约束，将 Agent 可变的 step/intent 名称与业务动作解耦；与「稳定幂等键＋严格防重」强基线比较，若完全等价则不单独计创新。

C2. **带证据有效期的状态机**：区分 `ack`、`positive_readback`、`external_consistency_proof`、`stale_receipt`、`unknown`；恢复准入基于明确假设，不把短时缺席当作负证据。

C3. **跨异构服务的成本/安全权衡**：对 read / idempotent / compensable / opaque / eventually consistent 接口区分安全动作集合；超过强 B3/B4/B5 才能声称改进。

C4（可选）. **依赖级恢复切片**：只有能在混合不可逆工作流里额外证明边界的情况下再做，不要跟 DART/AgentRewind 已做内容重复。

建议先锁定 **C1 + C2 + 可验证 B3 之外的 C3**；C4 等数据证明确有必要后再纳入。

## 最新必须新增的相关研究

1. DelAct, IWQoS 2026, DOI: 10.1109/IWQoS70441.2026.11661202：稳定意图、网关承诺/回放、补偿、事件日志，**直接重叠**。
2. LIMBO, arXiv:2609.29095（2026-09）：6 服务、12 故障、25,930 次 episode；不能把普通的故障矩阵/工具契约当新基准。
3. Verified Tool Calls, arXiv:2608.02645：验证前重试及幂等键 wrapper，**直接重叠**。
4. Cordon, arXiv:2606.17573：任务级语义事务、外部副作用隔离与预提交验证。
5. Atomix, arXiv:2602.14849：进度感知的事务性工具调用。
6. DART, arXiv:2605.23311：依赖与已提交下游条件下的语义恢复准入。
7. ACRFence, arXiv:2603.20625：Agent 语义回滚中的副作用重放问题。
8. SagaLLM, PVLDB 2025, DOI: 10.14778/3750601.3750611：Saga 事务和补偿方法。

注意：arXiv 论文不一定已同行评议；已确认 DelAct 是 IEEE IWQoS 2026 会议论文，SagaLLM 为 PVLDB 正式论文。

**创新否决条件**：C1–C3 若最终只重现 DelAct、Verified Tool Calls 和 LIMBO 的结果，则转换成狭窄边界研究/独立的负结果，不强行包装首创。
