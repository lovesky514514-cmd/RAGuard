# 多轮真实 HTTP 审计恢复实验

本实验**扩展既有 44 条固定条件协议**，不改变 Gateway、B5 或 Go 物理真值接口。两套方法均沿用研究适配器的只读审计和禁止恢复阶段二次写入规则；不能据此证明生产级 exactly-once。

## 执行

环境：Python 3.11+、Go 1.21+；只能访问本机回环沙箱。仓库根目录运行：

```bash
python -m unittest bench.test_audited_recovery_repeats -v
python -m bench.audited_recovery_repeats --repeats 3 --seed 20261123 --output results/audited_recovery_repeats
```

一轮为 `2 引擎 × 2 故障位置 × 11 证据变体 = 44` 次方法级执行。`--repeats 3` 执行 132 次，每次启动**新的 Go HTTP 进程和独立 SQLite 状态**。种子只打乱实验顺序及方法执行先后，**不改变故障类别、证据有效性或网络时延**。重复用于检验隔离、顺序依赖和可复现性；不得冒充 132 种不同场景。

## 保存的证据

- `episodes.csv`：重复编号、执行次序、固定条件和每条真实执行记录；包含未解决结果。
- `protocol.json`：完整实验范围、随机化方式、安全边界。
- `REPORT.md`：根据 CSV 实际统计的成功、未解决和恢复阶段新增写入。
- `falsification.csv`：对**输出副本**故意注入缺行、重复行、假确认、物理效果和计数篡改，检查评分器能否拒绝；不是新的 HTTP 实验或模型攻击。
- `SHA256SUMS.json`：上述四份文件的字节级校验和。

### 解释边界

本实验仍不包含真实 LLM、第三方服务、重复可随机化的网络故障或独立研究人员复现。共享的研究级写入阻断不是 Gateway 独立算法优势。即使 132 次都通过，也只能表述为**原 44 条固定条件在三个独立沙箱批次中的重复一致性**，不能据此报告真实生产故障概率或统计显著性。

若需要新的科学结论，下一阶段必须在冻结协议下引入真实的时序扰动、跨进程恢复和工具契约变化，并保持 B5 相同信息与预算。论文中的数值应以实际 CI 产物为准，不能复制本说明中的示例规模当成已执行结果。
