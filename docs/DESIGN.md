# 01 的实现边界

研究依据：`research/01_spec.md`。当前实现以 **确定性安全门 + 外部副作用账本 + 正向回读 + 故障注入**，不把研究设想包装成现有结果。

## 模块分工

- `raguard/model.py`：规范化请求与请求指纹。
- `raguard/identity.py`：验证业务引用，持久映射同一业务动作的不同 `step/intent`。
- `raguard/policy.py`：受信的工具性质，Agent 不能自行声明可重试。
- `raguard/ledger.py`：SQLite WAL 持久化、原子执行权、代次隔离、补偿审批状态。
- `raguard/recovery.py`：证据有效期和重试预算的纯判据。
- `raguard/gateway.py`：唯一恢复入口，选择执行 / 回放 / 安全重试 / 停止 / 人工补偿。
- `raguard/transport.py`：仅允许回环 HTTP，模拟第三方 API 的可观察证据。
- `raguard/http.py`：本地 HTTP 验签入口；不能信任 Agent 自填的业务引用。
- `mock/main.go`：独立于 Python 的真实 HTTP 服务与可注入故障，避免单进程假测试。

## 不变量

1. 同一可信 `(tenant, tool, business_ref)` 只绑定首次意图；语义变化时拒绝。
2. 同一规范化 `(tenant, task, intent)` 只能对应一种不可变化的请求指纹。
3. 第一次外部调用之前完成本地持久登记；只有持有当前代次者可写回结果。
4. 只有只读和服务器**真正实现稳定幂等键**的写操作允许重试。
5. `unknown` 表示证据不足；没有正向证据时不可逆、可补偿写都不得重放。
6. 补偿须人工批准；同一动作仅能认领一次；存在未解决的下游动作时不可单独补偿上游。
7. 业务依赖步骤必须已确认，才能启动后继步骤。重试父步骤时不重新运行已确认的上游节点。

## 已实现的动作

| 状态 / 证据 | 动作 |
|---|---|
| 尚未执行、依赖确认 | 首次执行 |
| 同一意图已确认，回读成功 | 正向证据回放 |
| 同一意图已确认，回读中断，可信回执未过期 | 标记 `receipt_only` 后回放 |
| 超时但正向回读证实成功 | Reconcile + Replay |
| 已验证稳定幂等键服务收到匹配回执，暂无法回读 | 仅在管理员明确设置 `authoritative_receipt` 时确认 `idempotent_ack` |
| 不可确认且工具支持只读/稳定幂等 | 按可配置 `RetryBudget` 安全调用；再次请求可安全认领 |
| 不可确认且操作不具备安全重试条件 | Stop / 人工处理 |
| 可补偿写、明确批准且无未解决的下游步骤 | 单次补偿认领 |

## 不能声称的事情

- **不保证通用 exactly-once**。沙箱的幂等写由 Go 服务强制保障；真实服务未必支持。
- `readback` 只能确认证据为正；查不到**不能证明没执行**。
- `inventory.read` 结果按逻辑意图回放，**不提供自动缓存过期/库存新鲜度保证**。
- 没有实现学习式风险模型、完整依赖子图最小重算、通用 MCP 协议代理、真实跨框架 Agent 或大规模统计。
- SQLite 只适用于单机低资源原型；不能以这套测试声称分布式一致性或生产级安全。
- 审批头是本机演示机制，不是生产身份系统；应用层实际部署还需要身份认证、TLS、审计权限管理。
