# 安全边界

## 可信边界

- **可信编排器**在 Agent 外生成业务引用并签名；Agent 仅提出调用请求，不具备签名密钥。
- **HTTP 入口**验签后传入 `VerifiedIdentity`；业务 JSON 不能自行声明可信身份。
- **业务引用登记表**按 `(tenant, tool, business_ref)` 原子绑定首次逻辑动作；参数、主体、依赖改变时拒绝。
- **副作用账本**保证单机条件下的执行认领和代次隔离；不提供跨数据库的分布式事务。
- **本地演示密钥**专为沙箱设计。`data/local_demo_identity.key` 不应拷贝到生产机器，不应被真实 Agent 或不可信插件读取。

## 无法保证的事情

1. **可信编排器本身误发两个合法业务引用**：网关会视为两笔业务，无法仅凭相同参数证明它们应合并。
2. **外部服务不支持稳定幂等键**：不能对未知提交执行通用安全重试。
3. **远程状态在回执之后被其他主体修改**：`receipt_only` 仅表示先前确认过，不证明当前状态仍然成立。
4. **业务身份撤销、跨租户授权和密钥轮换**：尚未实现，不得声称生产可用。
5. **权威成功回执的信任前提**：仅当服务端稳定幂等键和回执语义均被明确核实，`authoritative_receipt` 才可开启；当前只在本地 `orders.create` 模型启用。
6. **跨进程或跨机器部署**：当前原子性只覆盖各自 SQLite 事务，身份表与副作用账本未做跨库原子提交。

## 执行动作

| 状态 | 可执行动作 |
|---|---|
| 新写动作且可信身份已验证 | 首次登记并执行 |
| 同引用改写 `step/intent` | 映射到首次动作，不新增效果 |
| 同引用修改业务参数或主体 | 拒绝 |
| 已确认 + 正向回读可用 | 使用新证据回放 |
| 已确认 + 回读不可用 + 正向回执有效 | 回放旧结果并标记 `receipt_only` |
| 回执过期或曾未被确认 | 停止或按明确幂等契约处理 |
| 补偿动作 | 必须同时具有可信引用、既有确认记录及人工批准 |

注意：论文指标必须由外部业务状态真值判定，不能根据 HTTP 200 或网关自述推断任务成功。
