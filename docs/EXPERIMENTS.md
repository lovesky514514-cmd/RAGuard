# 实验定义与边界

## 真值与业务键

每个故障试验由固定的独立业务键和真实 Go 效果 ID 判分。业务键来自受控实验 fixture，不来自 Agent 可自由改写的 `intent`。同一业务动作修改意图仍计为重复效果；不同业务键被视为不同合法操作。沙箱实验不模拟生产平台跨租户身份授权。

- `acknowledged_success`：业务最终效果达到目标，调用方也收到确认。
- `physical_goal`：仅由独立效果事件判断的最终状态。
- `unsafe`：历史重复提交或额外未知业务提交，即使后来补偿也不会抹掉。
- `escalated`：未确认任务完成，需要停止或人工处理。
- `attempts/readbacks/extra_calls`：实际网络试验开销；`latency_ms` 是本轮策略时延，不含启动/销毁沙箱。

## 公平比较

单步骤方法 B0（不恢复）、B1（无约束固定重试）、B2（新意图指数退避）、B3（稳定幂等键+正向回读+硬停止）与 RAGuard 在同一工具/故障/强度/种子下配对，每次新建独立沙箱。单步故障六类：提交前断连、429、503；提交后断连、损坏 JSON、响应篡改。五档强度是 0/1/5/10/20%，另有 100% 强制故障冒烟。

多步骤 B4 是**本地参考 Saga**：使用 SQLite 持久步骤日志、正向确认、崩溃后不盲重发未知副作用及反向补偿。只与 RAGuard 在同一固定工作流、同一真实沙箱下比较。它不是 SagaLLM 官方代码，也不应与单步骤指标平均。

## 统计完整性

使用相同工具/故障/强度/编号/种子做严格配对。缺失配对、重复试验键不再静默忽略。Bootstrap 为描述性区间，综合不同业务和故障时必须同时报告分层分析。1% 故障下少量试验无法保证统计功效，未完成正式 RQ 验收。
