## 里程碑

### 2026-10 下旬：建立可执行的安全恢复原型

**主要交付：** 可信业务身份绑定、SQLite 持久化副作用账本、执行代次与租约、正向回读、安全重试门禁、人工批准的补偿路径，以及独立 Go HTTP 故障沙箱。

**关键取舍：**

- 工具超时不代表服务端未提交；回读为空或 404 不能作为重复写入的授权依据。
- 同一可信业务引用不能通过改写 `step/intent` 绕过去重；不同合法业务不能仅凭参数相同而合并。
- 物理副作用由 Go 沙箱独立评分，不能只用 HTTP 200 或网关自述推断成功。
- 禁止宣称通用 exactly-once、生产级支付安全或未经验证的第三方服务契约。

**碰壁与解决：** 修复了 Windows 双击闪退、服务启动窗口分散、无 Go 时无法运行演示、控制台编码差异和真实业务键统计失真等问题。具体见稳定分支 [问题记录 I-001— I-012](问题记录.md)。

**证据级别：** 核心接口与本地模拟回归已建立；真实第三方生产 API 和分布式部署没有验证。

### 2026-10-23：Windows 基础运行与故障测试入口

**主要交付：** Windows 启动、检查和实验入口；随包 Windows x64 Go 沙箱的 SHA-256 校验；单窗口进程管理、异常日志和有序关闭。

**实际观察：** 历史用户运行日志证实本地演示的启动、执行、结果回放和退出路径；后续无 Go 环境的故障 smoke 与工作流有成功日志。原有记录也明确存在实验/自检一度缺 Go 被拒绝的问题。

**边界：** 附带的 EXE 可以支持普通演示，不等于已使用当前用户机器的 Go 工具链从源码重新构建。首次运行证据也不能替代所有 Windows 版本的独立测试。

### 2026-10 下旬：强基线与证据预算研究（独立研究分支）

**主要交付：** 从 B0–B3 单步骤故障矩阵延伸到多步骤参考 Saga（B4），并增加独立持久化强基线 B5。研究分支还包含业务身份漂移、重启与并发恢复、TTL/在途请求不确定性、回读合并、证据时效、证据预算与在线来源调度等实验。

**碰壁与修正：**

- 早期与弱基线比较会夸大收益；纳入拥有同等业务身份和持久化能力的 B5 后，已观察到双方持平的实验。
- 一些条件规划收益可以被掌握同样元信息的手写规则复制；不能把常规规则包装成独有算法创新。
- 回读开销和延迟代价可能超过收益；增加相同预算、相同实际成本及分布漂移对照。
- 曾出现训练/测试分布泄漏、回读证明类型不匹配、冲突证据核验不充分、固定预算强制改选导致偏差等问题；研究分支保留负面结果与修复记录。
- `authenticated` 这样的模拟标签不等于密码学签名；本地客户端禁止二次写入的实验屏障也不等于服务端不可绕过的 fencing。

**证据级别：** 这些是独立研究分支中的原型和有限受控实验，不能笼统视为 `main` 的正式功能。逐条记录见 [研究分支问题台账](https://github.com/lovesky514514-cmd/RAGuard/blob/research/softwarex-submission/docs/%E9%97%AE%E9%A2%98%E8%AE%B0%E5%BD%95.md)，包括其当时标注的待 CI 项。

## 继续推进的验收条件

1. **源码可追溯**：复现者提供完整提交 SHA、干净工作区状态、系统与编译器版本，注明使用内置二进制还是源码重编译。
2. **强基线独立复现**：提交相同证据、身份、查询预算和故障条件下的 B5/RAGuard 配对原始案例、`protocol.json`、`REPORT.md` 及原始哈希。
3. **负面结果不删改**：完整报告不安全确认、重复副作用、未完成、回读次数、实际成本、时延及失败条件。
4. **外部有效性**：新随机种子与独立环境反复验证；若计划发表论文，补足与邻近方法的公平对照、永久可访问工件和原创性审查。
5. **隐私与发布**：全部对外材料须先脱敏；在没有确认许可、作者和版权范围前，不公开原始外部数据和私有日志。

### 2026-11-05：修复已启动服务与检查入口的端口冲突

外部 Windows 截图显示，`启动.bat` 保持运行期间占用本机 8181/8088；此时运行 `检查.bat`，Python 实验测试和 Go 检查已通过，但最终独立启动自检报 8181 端口占用，导致整体返回失败。

修复方式：保持 `启动.bat` 的互斥检测和现有进程不变；`检查.bat` 在完成静态校验、Python/Go 测试后探测端口，若任一端口占用，明确输出“独立启动、演示与退出自检已跳过（未执行）”，不终止既有进程，也不把跳过项算作 PASS。只有端口空闲才执行完整启动和清理自检。增加单端口和双端口占用测试。

**证据状态：** 截图确认原始失败发生在启停自检阶段；修复已提交，最新 CI 及真实 Windows 双窗口复测状态以对应提交的记录为准。详细问题见 [I-013](问题记录.md)。
