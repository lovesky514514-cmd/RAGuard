# RAGuard

**面向工具调用型 AI Agent 的安全恢复与外部副作用评测框架**

Python + Go · 本地可复现 · 中文说明 · Apache-2.0

> **为什么需要它？** Agent 请求创建订单后连接超时，并不代表订单没有创建。若把“调用失败”误当作“业务未执行”，直接重发请求就可能造成重复订单、重复工单或重复通知。

RAGuard 用可信业务身份、持久化执行账本和正向回读证据管理这一类不确定性。Python 负责请求校验、恢复决策与 SQLite 状态管理；Go 运行独立 HTTP 故障沙箱并记录真正发生的外部效果。所有演示只对本机模拟服务操作，不接入真实支付或业务平台。

**研究结论的边界：** RAGuard 是科研原型，不是生产安全网关，不保证通用的 exactly-once。现有同信息对照没有证明它优于独立持久化 B5 强基线；本仓库的测试通过不等于生产零风险，也不代表 SCI 论文已通过同行评审。

## 解决什么问题

| 情况 | 常见误判 | 本项目的处理思路 |
| --- | --- | --- |
| 创建订单后未收到响应 | 没有响应就是没有创建 | 先回读或确认幂等契约，不盲目重发 |
| Agent 改写步骤名称 | 新的 step 就是新的业务 | 通过可信业务引用识别原本业务身份 |
| 进程异常退出 | 本地内存丢失后可以重新执行 | 使用持久化账本、执行代次与状态检查 |
| 回读返回空结果 | 一定没有执行 | 证据不足，保守停止或等待 |
| 已执行操作需要撤销 | 直接调用反向 API | 先核对确认状态、依赖关系及人工批准 |

**关键原则：宁可明确返回“未知或需要人工处理”，也不为了提高表面成功率制造额外副作用。** 只有受信服务端确实提供稳定幂等契约的操作才可按相应规则重试。

## 核心模块与目录

```text
raguard/     请求模型、可信身份、SQLite 账本、恢复与 HTTP 入口
mock/        Go HTTP 故障沙箱、独立的实际副作用记录
bench/       配对故障实验、B0–B4 参考方法、评估统计
tests/       安全规则、端到端、并发和启动回归
scripts/     一键启动、自检、发布扫描、编码与哈希校验
docs/        使用方法、系统设计、安全边界、实验协议、问题记录
research/    研究计划及说明；不同分支的文件范围可能不同
results/     参考实验数据和本地生成结果
bin/         Windows x64 演示沙箱及其 SHA-256 校验值
```

| 核心文件 | 负责的工作 |
| --- | --- |
| `raguard/identity.py` | 绑定已验证业务引用与规范化请求 |
| `raguard/ledger.py` | 写前持久登记、状态、执行代次与补偿认领 |
| `raguard/gateway.py` | 根据证据判断首次执行、回放、重试或停止 |
| `raguard/policy.py` | 可信工具注册表及副作用类型 |
| `raguard/transport.py` | 访问本地 Go 沙箱并获取证据 |
| `mock/main.go` | 运行独立 HTTP 沙箱及受控故障 |
| `scripts/launcher.py` | 检查环境、管理进程、输出本地错误日志 |

进一步的模块边界与七条核心不变量，请阅读 [设计说明](docs/DESIGN.md)，避免仅凭 README 推断实现细节。

## 运行环境

| 用途 | 所需环境 |
| --- | --- |
| Windows x64 普通演示 | Python 3.11+；附带经 SHA-256 校验的 Go 沙箱 |
| Linux / macOS 源码运行 | Python 3.11+、Go 1.21+ |
| 完整研究与 CI 工具链 | Python 3.12、Go 1.23（以提交对应工作流为准） |
| 网络服务 | 仅本机回环；Go 默认 `127.0.0.1:8181`，Python 默认 `127.0.0.1:8088` |

运行前请完整解压工程，确认 Python 已加入 PATH。所有命令从仓库根目录执行；没有必要安装真实第三方 Agent、支付插件或业务 API。

### Windows 快速启动

1. 下载仓库 ZIP，完整解压到普通目录，不要在压缩包预览窗口内双击。
2. 双击 **`启动.bat`**：检查环境，启动 Go 和 Python 网关，执行本地订单示例。
3. 双击 **`检查.bat`**：检查源码编码、静态发布要求、测试和可用的运行环境。若 `启动.bat` 已占用 8181 或 8088，静态检查与单元测试仍继续，独立启动/演示/退出自检会明确标记为**跳过（未验证）**，不会终止正在运行的服务。
4. 双击 **`实验.bat`**：执行本地故障冒烟实验与工作流试验。

正常退出按 `Ctrl+C`；出现错误时窗口应保留诊断提示，不应自行关闭其他程序。日志保存在 `logs/运行日志.txt`。**分享日志前必须删去个人路径、凭据和任何真实数据。**

Windows 附带的 Go 沙箱便于普通演示；如果没有安装 Go，相关源码编译与测试应明确报告“未执行”，不能算通过。

## 本地接口与故障实验

在演示服务启动后，网关接收：

```text
POST http://127.0.0.1:8088/v1/calls
```

请求字段包括租户、主体、任务、步骤、业务意图、工具及参数。完整 JSON 示例、请求认证及故障变量请使用 [接口速查](docs/USAGE.md)，不要绕过可信业务身份机制。

主要返回语义：

| HTTP 状态 | 意义 | 推荐处理 |
| --- | --- | --- |
| `200` | 根据登记契约或正向证据成功确认 | 阅读 `action`、`state`、`evidence` |
| `202` | 可能仍在执行或需要等待 | 用相同可信业务身份检查 |
| `400/403` | 请求不合法、工具或授权被拒绝 | 检查参数和权限 |
| `409` | 冲突或提交状态不可确认 | 停止自动执行，不能更换意图绕过 |

可使用独立 Go 服务重现提交前断开、提交后回执丢失、回读不可用等情况。沙箱记录真实模拟副作用，评分器不依赖网关自己报告的“成功”。

## 科研复现：如何理解结果

当前稳定主分支提供本地故障测试、参考基线及可执行入口。更深入的持久化 B5、HTTP 证据审计与 SoftwareX 论文准备工作位于独立研究分支。**这些分支不一定包含相同文件，更不能混合不同提交的实验结果。**

独立复现至少需要记录：

1. 完整 Git commit SHA、分支、操作系统、Python 和 Go 版本；
2. 实际运行的命令、随机种子、故障矩阵与工具契约；
3. 原始 CSV、报告、物理效果日志及 SHA-256；
4. 失败、未知、未完成案例及与强基线持平的结果。

已有隔离研究的 44 个固定 HTTP 场景观察到两种恢复引擎持平，不能被误写成“RAGuard 已优于 B5”。其中共同实验适配器禁止恢复阶段二次外部写入，该安全边界不是 RAGuard 独有的算法增益。详细实验前提请见科研分支内的复现协议；永久归档和独立复现状态以实际材料为准。

## 代码约定与交接

- 新增 docstring 和必要注释使用**简体中文**，描述“为什么这样处理”，避免逐行复述显而易见的代码。
- 代码与文档保持 UTF-8 无 BOM；Go 使用 `gofmt`，避免长横线或等号装饰分隔。
- 优先小接口、可理解的函数和清晰命名，不为“看起来架构高级”引入无意义的包装层。
- 一项问题对应最小复现、修复及回归验证，统一追加在 [问题记录](docs/问题记录.md)。
- 正式交接时固定完整提交 SHA；测试未执行、CI 失败或真实平台未验证，必须分别如实说明。

默认 `main` 是稳定工程入口，科研实验分支独立保留。文档与规范维护分支不应顺带把未经审核的研究算法合入主分支。
